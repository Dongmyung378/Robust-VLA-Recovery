# Day 6 기준선 정책 연결

## 판정과 범위

로드맵의 6일차 완료 기준을 충족했다. 시드 378의 `pick_place` 환경에서 정책이
출력한 행동값으로 100 스텝을 연속 실행했고, 두 카메라 영상과 상태, 행동을
HDF5에 저장한 뒤 다시 검증했다.

설치된 LeRobot 0.6.1에는 SmolVLA 코드가 있지만 로컬 사전 학습 checkpoint는
없었다. 로드맵이 허용한 경량 기준선으로 입출력 연결부터 확인했다.
`lightweight_mlp_v1`은 시드로 고정한 미학습 정책이다. 이번 결과는 시스템 연결
검사이며 SmolVLA 또는 학습 정책의 성공률로 사용하지 않는다.

## 입출력 계약

- 입력은 agent와 wrist RGB, 34차원 로봇 상태, 선택한 지시문이다.
- RGB는 `uint8 / 255`로 `[0, 1]` 범위에 맞춘 뒤 카메라별 채널 평균과
  표준편차를 계산한다.
- 상태에는 원소별 `tanh`를 적용한다. 언어는 재현 가능한 16-byte 해시 특성으로
  바꾼다. 이 언어 특성은 데이터 흐름 검사용이며 의미 이해를 나타내지 않는다.
- 출력에는 `tanh`를 적용한다. arm 6축은 0.05, gripper는 1.0을 곱한 뒤
  `[-1, 1]`로 제한한다.
- 환경 제어 주기는 기존 태스크 계약과 같은 20 Hz다. 초기 10회 호출은 준비
  실행으로 처리하고 지연시간 통계에서 제외한다.

설정 로더는 알 수 없는 항목, 저장소 밖 경로, 잘못된 index, 범위를 벗어난
행동 크기, 100 스텝 미만의 실행을 거부한다.

arm 행동은 관측에 따라 변했고 설정한 0.05 범위를 넘지 않았다. gripper 출력은
약 -0.983이었다.

## 실패 후보 검토

두 카메라 영상의 0, 25, 50, 75, 100번 프레임을 확인했다. arm은 움직였지만
alphabet soup를 잡지 못했고, 목표 물체는 테이블 위에 남아 있었다. 100번째
100번째 스텝의 환경 성공도 false였다. 메타데이터에는 `grasp_failed`와 `stalled`을
후보로 기록했다. 이는 수동 검토 메모이며 Day 20의 자동 label이나 정답 label이
아니다.

## 검증 결과와 다음 범위

- WSL에서 단위 검사와 무결성 검사 46개가 통과했다.
- HDF5 구조, timestamp, 행동 범위, 출처 정보와 SHA-256을 확인했다.
- 두 카메라 프레임 202개를 모두 압축 해제해 수집 당시 픽셀 해시와 비교했다.
- 수동 검토 내용을 추가한 뒤에도 에피소드 재검증이 통과했다.
- `pip check`에서 깨진 dependency가 없었다.

Day 7에서는 이 미학습 시스템 기준선을 네 태스크와 시드 10개로 확장해 성공률,
GPU 메모리와 에피소드 지연시간을 측정한다. 학습된 정책과의 성능 비교는 2주차
시연 데이터 학습 이후 같은 평가 계약으로 수행한다.
